# Local MLX Tool-Calling and Rung 1 Verification (mlx-lm 0.31.3)

## Context

Prior secondary research (`proposal.md`) flagged `(verify)` on whether `mlx_lm.server` could parse OpenAI-style `tools` / `tool_calls` for agentic coding loops, because `mlx_lm/SERVER.md` did not document tool-call parsing. That raised the question of whether an external local server (`vllm-mlx`, `oMLX`, or LM Studio) was required before any local MLX model could pass the `tools` suite and back `private-local` in `opencode`.

## Findings

1. **`mlx-lm 0.31.3` includes native OpenAI `tools` / `tool_calls` parsing and prompt caching**:
   - `mlx_lm/tokenizer_utils.py` (`_infer_tool_parser`) inspects the loaded chat template and automatically binds a parser from `mlx_lm/tool_parsers/` (`json_tools`, `qwen3_coder`, `gemma4`, `glm47`, `kimi_k2`, `minimax_m2`, `mistral`, `pythonic`, `function_gemma`, `longcat`).
   - `mlx_lm/server.py` (`SequenceStateMachine` + `ToolCallFormatter`) tracks tool-call start/end token sequences during generation, parses tool arguments, emits structured OpenAI `choice.message.tool_calls` (and streaming SSE `delta.tool_calls`) objects with `finish_reason: "tool_calls"`, and parses historical `role: assistant` / `role: tool` messages on multi-turn follow-ups.
   - `mlx_lm/server.py` also maintains an in-memory `LRUPromptCache` (`--prompt-cache-size 10` by default) across turns.

## Decision and Scope

- **`qwen3-30b-a3b-2507-mlx-4bit` on stock `mlx_lm.server` (`0.31.3`) is cleared as the primary `private-local` backend**:
  - It is the only local model that passed all five automated gates in this repository: `sanity` (1/1), automated `v1` assertions (10/10), `tools` (4/4), streaming `tools_timing.json` (`tool_call_chunks: 1`, `ttft_seconds: 0.6442`), and the locked-down `opencode v2.0.32` standalone smoke test (`runs/2026-10-30-180432-opencode-smoke-qwen3-30b-a3b-2507-mlx-4bit-2aee4a3e-5qc2x4ag`, with `opencode_host_dirs_unchanged: true`, `network_observation_ok: true`, `non_localhost_sockets: 0`, `unconnected_udp_sockets: 0`, `server_request_count: 3`, `blocked_chat_requests: 0`, `only_read_tool_called: true`, `token_verified: true`).
- **`qwen3-coder-30b-a3b-mlx-4bit` is blocked from serving as the default `private-local` backend**:
  - While it passed `sanity` (1/1), `tools` (4/4), streaming `tools_timing.json` (`tool_call_chunks: 1`), and `opencode-smoke` (`runs/2026-10-30-180443-opencode-smoke-qwen3-coder-30b-a3b-mlx-4bit-d16dd7c9-1grk884d`, PASS in 6.5498s), it scored **6/10** on automated `v1` assertions (failing `bug-fix-python-batching`, `feature-plan-model-registry-status`, `structured-json-model-summary`, and `patch-like-edit-gitignore`).
- **Remaining caveats**:
  - Automated `v1` counts reflect the 10 deterministic assertions in `evals/suites/v1.yaml`; the 1-to-5 human rubric in `docs/plan.md` is operator-scored (`reviews/evals/<date>-v1.md`) and not claimed by these automated runs.
  - On `gemma-4-26b-a4b-it-optiq-mlx-4bit`, cell 3 (`tool-result-followup`) of `tools` emitted an empty reasoning channel that promptfoo prefixed as `Thinking:\n` before the final answer despite `enable_thinking: false`, and cell 9 (`patch-like-edit-gitignore`) of `v1` omitted the `diff --git` header line (9/10).
