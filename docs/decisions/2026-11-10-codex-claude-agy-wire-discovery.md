## Context & Question

Phase 5 of the post-`v0.1.3` roadmap (`plans/post-v013-roadmap.md`) required an empirical local loopback wire-capture study of OpenAI Codex CLI (`codex`), Claude Code (`claude`), and Google Antigravity CLI (`agy`) before deciding whether to ship direct Rung 1 / Rung 3 primary-planner launchers (`codex-local`, `codex-attested`, `claude-local`, `claude-attested`) or to keep OpenCode (`scripts/opencode-local` and `scripts/opencode-attested`) as the direct Rung 1 / Rung 3 primary planner while integrating `codex`, `claude`, and `agy` via native stdio MCP (`scripts/local-assist-server`) and CLI delegation (`scripts/delegate-local`).

## Methodology

All CLI probes ran inside a macOS `/usr/bin/sandbox-exec` Seatbelt profile (`test_sandboxed_codex_mcp_registration_and_two_turn_roundtrip`, `test_sandboxed_claude_mcp_registration_and_two_turn_roundtrip`, and `test_sandboxed_agy_mcp_registration` in `tests/test_local_assist.py`, with per-client missing-binary skips verified by `test_partial_cli_availability_skips_missing_clients_individually`) with:

1. **Loopback-only network isolation**: `(deny network*)` with explicit `(allow network* (local ip "localhost:*"))`, `(allow network* (remote ip "localhost:*"))`, and `(allow network* (remote unix-socket))`.
2. **Disposable filesystem & config isolation**: `(deny file-write*)` outside the temporary scratch directory and `(deny file-read*)` over the operator's real `~/.claude.json`, `~/.claude`, `~/.codex`, `~/.gemini`, and `~/.config/opencode` paths, combined with an allowlisted child environment (`_build_isolated_cli_probe_env`) that strips ambient `OPENAI_*`, `ANTHROPIC_*`, `CLAUDE_*`, `CODEX_*`, `GOOGLE_*`, `GEMINI_*`, `LOCAL_ASSIST_*`, and proxy variables and redirects `HOME`, `TMPDIR`, `XDG_*`, `CODEX_HOME`, and `CLAUDE_CONFIG_DIR` into the scratch root.
3. **In-process `127.0.0.1` loopback HTTP capture**: Ephemeral `127.0.0.1:<port>` HTTP servers captured exact outbound request paths, auth/version/beta headers, tool schemas, and multi-turn tool-result payloads, with sanitized results recorded in `runs/2026-11-10-agent-wire-discovery-and-mcp/summary.json`.
4. **Explicit fixture boundaries across the three test layers (`FREE-INFERENCE-MCP-001 F2`)**:
   - **Unwrapped entry-point, lifecycle, and hostile-proxy layer** (`test_registered_entrypoint_bypasses_hostile_proxy_and_resolves_workspace_root` and `test_open_loopback_http_bypasses_env_and_system_proxies_and_redirects`): Launches the unmodified `scripts/local-assist-server` (across both the `python3` fallback and `.venv/bin/python` branches) and `scripts/delegate-local` from a separate caller `cwd` (`LOCAL_ASSIST_WORKSPACE_ROOT`) with a hostile `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` environment (`NO_PROXY` unset) and a minimal `PATH` omitting `/usr/sbin`. Exercises the real `delegate_task` (`context_path`) and `extract_fields` tool implementations, real `scripts/verify-served-model --require-offline` listener verification, `open_loopback_http` (`ProxyHandler({})` + redirect refusal), and `runs/local-assist/` audit-log redaction against a live loopback HTTP backend (`0` proxy requests).
   - **Dual-framing & `--auto-serve` state-machine layer** (`test_mcp_stdio_content_length_and_newline_roundtrip` via `run_wrapped_mcp.py`): Exercises `Content-Length:` and newline-delimited JSON-RPC framing plus `ensure_local_model_served()` cold-start transitions using patched `load_models` / `resolve_endpoint` and a mocked `serve-model` / `verify-served-model` subprocess runner over an isolated child environment.
   - **Seatbelt-sandboxed native CLI wire-capture layer** (`test_sandboxed_codex_mcp_registration_and_two_turn_roundtrip`, `test_sandboxed_claude_mcp_registration_and_two_turn_roundtrip`, and `test_sandboxed_agy_mcp_registration` via `mock_local_assist_server.py`): Runs the real `local_assist.server` stdio JSON-RPC dispatcher, schemas, and `ToolAnnotations` inside `/usr/bin/sandbox-exec`, with `extract_fields` stubbed to return deterministic `{"extracted": {"amount": 42}, "missing_required": [], "extraction_note": null}` so the CLI wire probes isolate client protocol, namespace, and approval behavior without loading MLX weights.

### 2. Native Stdio MCP Interoperability (`scripts/local-assist-server`)

All four agents natively support stdio MCP servers (`propose_eval_prompts`, `extract_fields`, `compress_context`, `delegate_task`):

- **Framing**: `local_assist/server.py` auto-detects both `Content-Length:` header framing and newline-delimited JSON-RPC (`read_message_with_framing` / `write_message`), matching the stdio transport used by `opencode`, `codex`, `claude`, and `agy`.
- **Truthful `ToolAnnotations` and Codex approval semantics (`R2-MAJOR-1`)**:
  - Every `local_assist` tool persists local run audit logs under `runs/local-assist/` (`local_assist/logging.py`) and, when `--auto-serve` (`LOCAL_ASSIST_AUTO_SERVE=1`) is enabled, can invoke `scripts/serve-model --started-by auto-serve` to start a persistent detached local MLX server and write PID records (`local_assist/lifecycle.py`).
  - Accordingly, `local_assist/server.py` advertises `annotations: {"readOnlyHint": False, "openWorldHint": False}` on all four tools (truthfully declaring that calls are not purely read-only while remaining locked to localhost endpoints).
  - In `codex-cli 0.164.0`, MCP tools are advertised inside a `"type": "namespace"` entry (`"name": "mcp__local_assist"`). Because `readOnlyHint` is `False` (and `destructiveHint: False` is intentionally omitted so Codex does not auto-bypass approval), non-interactive `codex exec -s read-only` sessions (`approval: never`) gate tool calls with `"MCP tool call requires approval, but approval policy is never"` unless the operator explicitly approves the tool in `$CODEX_HOME/config.toml` via `[mcp_servers.local_assist.tools.<tool_name>] approval_mode = "approve"`.
- **Timeout budget alignment (`PLAN-MINOR-1`)**:
  - `local_assist` defaults to a 120-second request budget (`LOCAL_ASSIST_TIMEOUT_SECONDS = 120` in `local_assist/client.py`), shared across optional `--auto-serve` startup (`DEFAULT_AUTO_SERVE_WAIT_SECONDS = 45.0`), health checks, and completion.
  - Because `codex` defaults to `tool_timeout_sec = 60`, `[mcp_servers.local_assist]` should set `tool_timeout_sec = 180` (matching OpenCode's `timeout: 180000` in `config/opencode-private-local.json.tmpl`). If `LOCAL_ASSIST_TIMEOUT_SECONDS` is increased above 120s, set `tool_timeout_sec >= LOCAL_ASSIST_TIMEOUT_SECONDS + 60`.
- **Loopback proxy bypass and redirect refusal (`FREE-INFERENCE-MCP-001 F1`)**:
  - Bare MCP registrations (`codex mcp add`, `claude mcp add`, `agy mcp add`) inherit the calling host's environment and OS network configuration rather than `opencode-local`'s stripped launcher environment.
  - `local_assist/client.py` (`open_loopback_http`) and `scripts/verify-served-model` (along with local health/smoke callers) build openers with `ProxyHandler({})` and a redirect-refusing `HTTPRedirectHandler`, rejecting non-`http(s)` schemes, non-loopback hosts, URL userinfo, HTTP `3xx` redirects, ambient `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` variables (even when `NO_PROXY` is unset), and macOS SystemConfiguration proxy discovery (`_scproxy`).

## Decision

1. **No protocol-translation proxy in front of `se-key-proxy` or `mlx_lm.server`**:
   - We explicitly reject adding a `/v1/responses` -> `/v1/chat/completions` or `/v1/messages` -> `/v1/chat/completions` translation proxy in front of Rung 1 (`mlx_lm.server`) or Rung 3 (`se-key-proxy`).
   - Translating stateful Responses API items (`item_id`, encrypted reasoning items, namespace-scoped `function_call` / `function_call_output`) or Anthropic Messages API blocks (`cache_control`, `thinking` signatures, beta headers) into stateless Chat Completions is lossy, brittle across CLI upgrades, and expands the local proxy surface in front of `se-key-proxy`.
2. **Primary Rung 1 / Rung 3 planner**:
   - Keep `scripts/opencode-local` (Rung 1) and `scripts/opencode-attested` (Rung 2/3) as the direct primary-planner launchers when the entire coding session must stay on Rung 1 (`local`) or Rung 2/3 (`enclave_runtime_attested`).
3. **First-class Rung 1 MCP & CLI delegation for `codex`, `claude`, and `agy`**:
   - Support `codex`, `claude`, and `agy` via native stdio MCP (`scripts/local-assist-server`) and CLI delegation (`scripts/delegate-local`), documented with copy-paste registration, timeout tuning (`tool_timeout_sec = 180`), explicit per-tool approval configuration, and telemetry-hardening settings in `docs/local-assist-server.md` and `docs/runbooks.md`.
   - Preserve explicit rung accounting: when a Rung 4/5 planner (`codex`, `claude`, `agy`) calls a `local_assist` tool, reading `context_path` in `delegate_task` keeps the raw file off the outbound prompt during the local Rung 1 inference call, but the returned tool output enters the calling planner's session context and data-control rung.
