# Architecture & Data-Control Design (`free-inference`)

Status: Active architecture reference. Base workbench upgrades (`local_assist/registry.py`, multi-PID lifecycle, `evals/suites/tools.yaml`), the 5-rung data-control ladder, full Rung 1 (`local`) automated verification (`sanity`, `v1`, `tools`, streaming `tools_timing.json`, and locked-down `opencode-smoke`), and the Rung 3 (`enclave_runtime_attested`) Tinfoil attestation and capability trial (`tinfoil-deepseek-v4-1-flash`, `tinfoil-gpt-oss-120b`, `tinfoil-glm-5-3`, and `tinfoil-kimi-k3` via `tinfoil-proxy v0.2.9` + `se-key-proxy`; see `docs/attestations/2026-10-31-tinfoil-rung3-trial.md`) are active in this repository. Items marked **(verify)** require live confirmation against provider endpoints or tooling before promotion.

## Goal

"Free" as in freedom, not price:

1. **Data control**: Keep control of prompts, code, and outputs as far as the market practically allows. Never send data to a lower-control rung when a higher-control rung passes the capability bar for the task.
2. **Freedom of use**: No vendor usage policy or silent middleware deciding what legitimate work the model will perform (including defensive security and red-team evaluation). Tool calling must work reliably on every rung.
3. **Verifiable boundaries**: Prompts leave the machine for an enclave only through a local verifying proxy, with explicit distinction between **weight-attested** enclaves and **runtime-only attested** enclaves.
4. **No silent downgrades**: Every provider and model is judged with the same promptfoo suites (`sanity`, `v1`, `tools`), and no client or gateway ever silently falls back to a lower-control rung.

## The 5-Rung Data-Control Ladder

Rather than a binary "attested vs. not", `local_assist/registry.py` orders every endpoint along five explicit data-control rungs (`DATA_CONTROL_RUNGS`):

| Rung | `remote_trust.tier` | What is verified | Who can still see or alter behavior |
|---|---|---|---|
| **1** | `local` | Local weights (`mlx-lm`), local process on `127.0.0.1:8080`, `HF_HUB_OFFLINE=1` forced by `scripts/serve-model` | Nobody |
| **2** | `enclave_weights_attested` | Hardware TEE + local proxy verifies runtime measurement **and** registry records a 64-hex `weights_hash`, pinned `weights_source` (`<org>/<repo>@<40-hex-sha>`), `weights_verified_by`, `weights_verified_date`, and a committed `weights_verification_artifact` path (relative to the repository root, not under gitignored `runs/`) reproduced from an audited upstream Hugging Face commit | Hardware root of trust (AMD/Intel/NVIDIA) and physical memory-bus attackers (`TEE.fail`) |
| **3** | `enclave_runtime_attested` | Hardware TEE + local proxy verifies enclave runtime and provider-signed manifest (`tinfoil-proxy` default or `privatemode-proxy` with pinned manifest), but model weights are not independently reproduced/pinned by the client | Same as Rung 2, **plus** provider build pipeline could serve altered/quantized weights under the claimed `served_model_id` |
| **4** | `zdr_contract` | Contractual zero data retention over standard TLS (e.g., DeepInfra, Fireworks with `store=False`) | Provider infrastructure sees plaintext in memory; subject to legal holds, abuse logs, or content filters |
| **5** | `standard_api` | Retaining or unspecified third-party API | Provider logs, retains, or trains on prompts/outputs |

### Why Rungs 2 and 3 are distinct (Weight Attestation Check)

Enclave attestation proves the code booted inside the CVM, not automatically which model weights were mounted after boot:

- **Tinfoil (`modelwrap` + `dm-verity`)**: Tinfoil packages Hugging Face revisions (`<org>/<repo>@<commit_sha>`) inside a digest-pinned Docker container ([`tinfoilsh/modelwrap`](https://github.com/tinfoilsh/modelwrap); [`cmd/modelwrap`](https://pkg.go.dev/github.com/tinfoilsh/modelwrap/cmd/modelwrap)) into a deterministic read-only EROFS image (`MWP` / `EMWP`) and computes a `dm-verity` Merkle root hash declared in `tinfoil-config.yml` ([`tinfoilsh/tinfoil-config`](https://github.com/tinfoilsh/tinfoil-config); [Tinfoil docs](https://docs.tinfoil.sh/)).
  - **Rung 3 (`enclave_runtime_attested`)** is the maximum posture on this Mac for Tinfoil's models (`gpt-oss-120b` at $0.15/$0.60 per 1M tokens, `deepseek-v4-1-flash` at $0.65/$1.45 ($0.13 cached), `glm-5-3` at $1.80/$5.75 ($0.45 cached), `kimi-k3` at $4.00/$20.00 ($0.80 cached), and `gemma4-31b` at $0.40/$1.00; all verified against live `/.well-known/tinfoil-proxy` and `tinfoil-config.yml` on 2026-10-31 in `docs/attestations/2026-10-31-tinfoil-rung3-trial.md`): `tinfoil-proxy v0.2.9` verifies the AMD SEV-SNP router enclave (`inference.tinfoil.sh`, `tinfoilsh/confidential-model-router@v0.0.168`), pins its TLS SPKI SHA-256 (`6af2bd2e...`), and encrypts request/response bodies to its attested X25519 HPKE key (`2635ac6c...`), while the router enclave attests and pins each backend Intel TDX / AMD SEV-SNP model enclave (`manager/verification.go`). An independent tracker notes that "the verifier explicitly does not independently reproduce the build" ([awesome-private-inference](https://amiller.github.io/awesome-private-inference/)). Because `modelwrap` computes the `dm-verity` root hash over the packed EROFS image of the full weight directory inside a container (`195.8 GB` for `gpt-oss-120b`, `510.3 GB` for `deepseek-v4-1-flash`, `464.9 GB` for `glm-5-3`, `1.56 TB` for `kimi-k3`), independently reproducing `weights_hash` requires a container runtime and hundreds of gigabytes of scratch disk beyond this host's budget. Note: although a 2026-10-21 directory snapshot reported attestation "unreachable" for DeepSeek V4.1 Flash, GLM 5.3, and Kimi K3 ([confidentialinference.net](https://confidentialinference.net/providers/tinfoil)), live verification on 2026-10-31 confirmed all five coding models are actively attested by `tinfoilsh/confidential-model-router@v0.0.168` (`https://inference.tinfoil.sh/.well-known/tinfoil-proxy`) because backend model enclaves (`*.tinfoil.containers.tinfoil.dev`) are reachable only from the attested router enclave on Tinfoil's internal network.
  - **Rung 2 (`enclave_weights_attested`)** is granted by `local_assist/registry.py` only when `remote_trust` also records a verified 64-hex `weights_hash`, pinned `weights_source` (`<org>/<repo>@<40-char-sha>`), `weights_verified_by`, `weights_verified_date`, and a committed `weights_verification_artifact` path (for example `docs/attestations/<model>.json`, not under gitignored `runs/`).
- **Privatemode (Edgeless Systems `Contrast` + `dm-verity`)**: Privatemode / Contrast binds a `dm-verity` block-device root hash and container digests into a Contrast runtime policy manifest (`manifest.json`) anchored in SEV-SNP `HOST_DATA` or TDX `MRCONFIGID` ([Contrast attestation docs](https://docs.edgeless.systems/contrast/en/latest/architecture/attestation.html); [Contrast manifest docs](https://docs.edgeless.systems/contrast/en/latest/usage/manifest.html); [Privatemode security](https://www.privatemode.ai/security)).
  - **Rung 3 (`enclave_runtime_attested`)** requires running `privatemode-proxy` with a **pinned manifest** (its default automatic mode can adopt a new provider manifest after a validation failure; [awesome-private-inference](https://amiller.github.io/awesome-private-inference/)) **(verify pinning flags)**. Because no public reproducible packing tool equivalent to `modelwrap` was found to recompute Privatemode's `dm-verity` root hash from an upstream Hugging Face commit, Privatemode tops out at Rung 3. In addition, if `privatemode-proxy` requires holding the API key in its own process rather than passing through `se-key-proxy`'s `Authorization: Bearer` header (N2), it will require a dedicated unix-socket or network-namespace design during the Privatemode trial plan.

## Shape

### Phase 1-2 (Current: Direct Local + Single Attested Proxy, No Gateway Yet)

Until a second remote provider is active, skip the LiteLLM gateway (one fewer component that can log or leak) and point `opencode` directly at the localhost endpoints:

```
  opencode (alias: private-local)    ──────> mlx_lm server :8080       (Rung 1: local, qwen3-30b-a3b-2507-mlx-4bit, launched via scripts/opencode-local)
  opencode (alias: private-attested) ──────> se-key-proxy :8081 -> tinfoil-proxy :9081 (Rung 3: enclave, tinfoil-deepseek-v4-1-flash, launched via scripts/opencode-attested)
  local-assist MCP                   ──────> mlx_lm server :8080       (Rung 1: local, newline-delimited + Content-Length stdio framing)
  promptfoo (scripts/eval)           ──────> per-model apiBaseUrl in models.yaml
```

- **Everyday Rung 1 launcher (`scripts/opencode-local` + `config/opencode-private-local.json.tmpl` + `scripts/opencode-local-e2e`)**:
  - Enforces Rung 1 (`trust_tier == "local"`), `capabilities.tool_calling == true`, and `routing.private_local == "cleared"` (cleared only on `qwen3-30b-a3b-2507-mlx-4bit` unless `--allow-uncleared-model` is passed).
  - Auto-starts/verifies `qwen3-30b-a3b-2507-mlx-4bit` on `http://127.0.0.1:8080/v1` (with `HF_HUB_OFFLINE=1`) and fails closed on exit code `3` (`EXIT_MODEL_MISMATCH`) if another model is occupying port `8080`.
  - Configures `enabled_providers: ["private-local"]`, `model` and `small_model` set to `private-local/qwen3-30b-a3b-2507-mlx-4bit` (so the background `title` agent stays on Rung 1), `lsp: false`, `formatter: false`, `webfetch: false`, `websearch: false`, `context7*: false`, default catch-all permission `"*": "ask"` (with `context7*: "deny"`), and `mcp.servers.local_assist` (`codemode: false`, `timeout: 180000`).
  - Isolates `opencode`'s own config, state, cache, and logs under `.home/opencode-private-local/` and sets `OPENCODE_DISABLE_PROJECT_CONFIG=1` so untrusted workspace `opencode.json` / `.opencode/` files are ignored. ### Freedom of Use (`usage_policy`)

A private endpoint that breaks tool calls or censors defensive security prompts reduces freedom of use:
- Every candidate must pass `scripts/eval tools <model-id>` before backing an agent alias.
- `remote_trust.usage_policy` is validated against `{"unrestricted_local", "enclave_no_inspection", "provider_filtered", "provider_terms_apply", "unknown"}`. It defaults to `unknown` on all non-local rungs so unverified provider policies are never silently recorded as unrestricted, and `unrestricted_local` is rejected off Rung 1.

## Security & Scope Boundaries

1. **Private-coding admission gate (`local_assist/client.py`)**:
   - Admits Rung 1 (`local` on localhost) by default.
   - Admits Rung 2 (`enclave_weights_attested`) and Rung 3 (`enclave_runtime_attested`) via a localhost proxy **only** when explicitly opted in with `LOCAL_ASSIST_ALLOW_ATTESTED_TEE=1` **and** `routing.private_attested == "cleared"` (or when an uncleared candidate model is explicitly overridden via `LOCAL_ASSIST_ALLOW_UNCLEARED_TEE=1` / `--allow-uncleared-model` in `scripts/opencode-attested`).
   - Blocks Rung 4 (`zdr_contract`) and Rung 5 (`standard_api`) from `local-assist` private coding workflows.
2. **Outbound firewall (LuLu)**:
   - On Rungs 2-3 (enclave proxy mode), `se-key-proxy` connects only to the local vendor proxy on `127.0.0.1:<upstream_port>` and needs zero external network egress; only the vendor proxy (`tinfoil`) may reach its enclave/Sigstore domains. On Rungs 4-5 (direct HTTPS proxy mode), only `se-key-proxy` may reach the pinned `upstreamBaseUrl` host on port 443. `opencode`, `promptfoo`, and local MLX servers get no external egress.
3. **Out of scope today (Agent-Loop Prompt Injection)**:
   - **Agent-side prompt injection**: Even on Rung 1 (`local`) or Rung 2 (`enclave_weights_attested`), a coding agent can be hijacked by untrusted repo files or tool outputs. Guarding the agent loop against tool-output injection is out of scope for the inference transport layer and requires operator approval of interactive tool calls (`edit`, `write`, `patch`, `bash`).
4. **Hardware-backed API credential isolation (`tools/se_key_proxy/main.swift`, `local_assist/se_key.py`, `scripts/se-key`)**:
   - **No plaintext or environment-variable API keys**: `local_assist/registry.py` rejects `apiKeyEnvar` and plaintext `apiKey` on all non-local rungs (Rungs 2-5) and requires `runtime: proxy` on a localhost `apiBaseUrl` plus `promptfoo_provider.apiKeyKeychainService` (`free-inference.<service>`). Enclave tiers (Rungs 2-3) additionally require a `serve_command` and forbid `upstreamBaseUrl`, while Rungs 4-5 require a validated `https://<host>/v1` `upstreamBaseUrl` on port 443 and forbid `serve_command`.
   - **Secure Enclave + Touch ID sealing**: `./scripts/se-key store <service>` generates a per-service hardware-bound P-256 private key inside the Apple Silicon Secure Enclave with `SecAccessControlCreateWithFlags(..., kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly, [.privateKeyUsage, .biometryCurrentSet])` (so the SE key is usable after first unlock since boot, while every unseal still requires a live Touch ID match), seals the operator's API key via ECIES (`P256.KeyAgreement` + `HKDF<SHA256>` + `AES.GCM` with service AAD), and stores only the JSON envelope (`se-ecies-v1`) in the macOS `login` Keychain (`/usr/bin/security`).
   - **Live Touch ID unlock, kernel-verified loopback upstream (`F1`), and loopback auth-injecting proxy (`se-key-proxy`)**: When `./scripts/serve-model <model-id>` starts a non-local proxy, it verifies the Swift source hash, compiler version, build stamp (`bin/.se-key-proxy.stamp`), and binary SHA-256 + `codesign -v --strict` signature, writes a provisional `"status": "starting"` PID record with a per-invocation `startup_nonce` before spawning any child (`F2`), and launches `bin/se-key-proxy proxy`. `se-key-proxy` sets `LAContext.touchIDAuthenticationAllowableReuseDuration = 0`, prompts the operator for a live Touch ID tap displaying the service, upstream destination, allowed model, request cap, and TTL, unseals the API key into process memory (`PT_DENY_ATTACH`), and listens on `127.0.0.1:<port>`. On Rungs 4-5 (`upstreamBaseUrl: https://...`), the decrypted API key exists only inside `se-key-proxy` process memory and is sent over TLS to the pinned upstream host. On Rungs 2-3 (loopback vendor-proxy mode, `127.0.0.1:<port>` -> `127.0.0.1:<upstream_port>`), `se-key-proxy` requires `--upstream-pid <upid>`, verifies via `<libproc.h>` (`proc_pidinfo` + `proc_pidfdinfo`) that `upid` (matching its startup timestamp `pbi_start_tvsec`/`pbi_start_tvusec` and `pbi_status != SZOMB`) owns the non-`SO_REUSEPORT` `TSI_S_LISTEN` kernel PCB (`soi_pcb`) on `127.0.0.1:<upstream_port>` both at startup and after each `connect()` before writing a single byte of the request or `Authorization` header (`F1`), and watches `upid` via `EVFILT_PROC` (`NOTE_EXIT`); on each forwarded request, the plaintext `Authorization: Bearer <real_api_key>` header crosses `lo0` to the verified vendor proxy socket and is transiently held in the vendor proxy (`tinfoil`) process memory under standard macOS same-UID isolation (capturing `lo0` requires `/dev/bpf*` read permissions, so the attestation trial requires a pre-flight `ls -l /dev/bpf0` check confirming `crw------- root wheel` with no `access_bpf` / `ChmodBPF` group access; `AF_UNIX` `LOCAL_PEERPID` or an inherited listening fd is the preferred future transport if `tinfoil` adds Unix socket support, `P5`). Callers (`verify-served-model`, `timing`, `eval` via `scripts/with-session-token`, and `opencode-smoke`) authenticate to `se-key-proxy` using a random per-session bearer token (`se-session-<64-hex>`, mode `0600` in `runs/.se-session-<slug>.token`, passed via `LOCAL_ASSIST_SESSION_TOKEN` in child env and never written to `suite.yaml` or `opencode.json`); `se-key-proxy` validates the caller token, `Host` header, path allowlist (`/v1/models`, `/v1/chat/completions`), single `"model"` key (with full UTF-16 surrogate-pair decoding, `F3`), request size, `max_tokens` cap, non-blocking downstream write deadline (`--stream-timeout-seconds`, `F4`), and session request/TTL limits before injecting `Authorization: Bearer <real_api_key>` to the fixed upstream. `scripts/write-metrics` and `scripts/opencode-smoke` also record a full-tree `session_token_scan` manifest (`roots`, `missing_roots`, `excluded_dirs`, `files_scanned`, `bytes_scanned`, `files_skipped`, `matches_found`, `redactions_applied`, `remaining_unredacted_matches`, `matched_files`) in `metrics.json` and `summary.json` (if `.home/.promptfoo/promptfoo.db` or `.home/opencode-private-local` ever records a historical token leak, recovery is `rm -f .home/.promptfoo/promptfoo.db` or `rm -rf .home/opencode-private-local`, `P3`/`V2`/`R2-F2`).
   - **Trust boundary against a compromised same-UID local agent**: Because the repository checkout is writable by the current macOS user, a compromised local agent running under the same UID could modify repo scripts or `bin/se-key-proxy` before the next Touch ID tap unless the helper binary is installed root-owned (`root:wheel`, mode `0755`) outside the agent's write authority (for example `/usr/local/libexec/free-inference/se-key-proxy`) and referenced via `FREE_INFERENCE_SE_PROXY_BIN` (which `local_assist/se_key.py` verifies is owned by `root` with no group/world-writable path components).
5. **Enforceable unattended worker security profile (`local_assist/security_profile.py`, `scripts/opencode-local --security-profile`, `scripts/opencode-attested --security-profile`)**:
   - **Two-layer defense-in-depth (OpenCode runtime + macOS Seatbelt `/usr/bin/sandbox-exec`)**: Supervisors (`AgentComms` or operator scripts) supply a `free-inference/worker-security-profile/v1` YAML/JSON profile (or `--unattended-worker` preset); `opencode-local` and `opencode-attested` compile it into both a per-invocation `opencode.json` (fail-closed `"*": "deny"` permission baseline, allowed/denied built-in tools, allowed/denied MCP servers and tools, `allow_subagents: false` default, and `--standalone` private runtime enforcement) and a mandatory Apple Seatbelt kernel profile (`worker.sb`).
   - **Bounded filesystem read/write authority and self-modification prevention**: `worker.sb` denies `file-read-data` under `/Users` (plus `/Volumes`, `/Network`, `/private/var/folders`, `/private/tmp`, `/private/var/tmp`), allows reads only within canonicalized `read_roots`, `write_roots`, the ephemeral `isolated_home`, and validated read-only system/toolchain roots, denies `file-write*` globally except within canonicalized `write_roots` and mutable `isolated_home` subdirectories (`.tmp/`, `.local/`, `.cache/`), denies writes to `free-inference` runtime code/scripts/config/venv/Python installation paths (`_collect_runtime_write_deny_paths`) even inside a containing `write_root`, and re-applies final `(deny file-write* ...)` overrides on `isolated_home/opencode.json`, `isolated_home/worker.sb`, `isolated_home/bin`, `isolated_home/lib`, `isolated_home/runtime`, `isolated_home/.config`, `isolated_home/.worker-owner.json`, `isolated_home/.unconfirmed-process-group.json`, `isolated_home/verified-models.json`, `isolated_home/pyvenv.cfg`, and all canonicalized `protected_paths` (including `.git` with a narrow working-tree plumbing allowlist) so the worker can never modify or relax its own profile, runtime code, or hook scripts.
   - **Loopback-only two-tier kernel network filter, immutable staged `local_assist` runtime, and token relay**: `worker.sb` enforces `(deny network*)` with `(process-path ...)` loopback port allowlists (blocking non-loopback IPv4/IPv6, raw sockets, and arbitrary `AF_UNIX` sockets unless `allow_ssh_agent: true`). When `mcp.enable_local_assist: true`, a dedicated read-only Mach-O copy `<isolated_home>/bin/local-assist-python` (`0500`) and immutable runtime snapshot `<isolated_home>/runtime` (`0400`/`0500`, bound via `local_assist_runtime.pth` and run with `-I -m local_assist.server`) isolate `localhost:8080` access and imports from worker processes. In `opencode-attested`, the parent launcher runs an in-process `_WorkerTokenRelay` on `127.0.0.1:<ephemeral_port>` with a single-worker random token (`worker-relay-<64-hex>`) and finite positive `max_session_usd` ceiling so `se-session-*` tokens and `runs/` never enter the worker's environment, config files, or readable filesystem.
   - **Descriptor-pinned lifecycle, process-group reaping, and audit log harvesting**: The launcher runs the sandboxed worker inside a dedicated process group (`run_worker_sandbox_lifecycle`) with confirmed `SIGTERM` -> `SIGKILL` escalation (`.unconfirmed-process-group.json`), multi-pass start-time-revalidated reaping (`ps eww` + fail-closed `lsof -d cwd`), nonblocking `O_NONBLOCK` + `S_ISREG` + size-capped + row-deduplicated log harvesting into `runs/local-assist/`, and descriptor-pinned `openat`/`unlinkat`/`fchmod` tree removal (`_safe_rmtree_nofollow`).
