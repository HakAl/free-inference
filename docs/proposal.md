## Goal

"Free" as in freedom, not price:

1. **Data control**: Keep control of prompts, code, and outputs as far as the market practically allows. Never send data to a lower-control rung when a higher-control rung passes the capability bar for the task.
2. **Freedom of use**: No vendor usage policy or silent middleware deciding what legitimate work the model will perform (including defensive security and red-team evaluation). Tool calling must work reliably on every rung.
3. **Verifiable boundaries**: Prompts leave the machine for an enclave only through a local verifying proxy, with explicit distinction between **weight-attested** enclaves and **runtime-only attested** enclaves.
4. **No silent downgrades**: Every provider and model is judged with the same promptfoo suites (`sanity`, `v1`, `tools`), and no client or gateway ever silently falls back to a lower-control rung.

## The 5-Rung Data-Control Ladder

Rather than a binary "attested vs. not", `local_assist/registry.py` orders every endpoint along five explicit data-control rungs (`DATA_CONTROL_RUNGS`):

| Rung | `remote_trust.tier` | What is verified | Who can still see or alter behavior |
|---|---|---|---|
| **1** | `local` | Local weights (`mlx-lm`), local process on `127.0.0.1:8080`, `HF_HUB_OFFLINE=1` forced by `scripts/serve-model` | Nobody |
| **2** | `enclave_weights_attested` | Hardware TEE + local proxy verifies runtime measurement **and** registry records a 64-hex `weights_hash`, pinned `weights_source` (`<org>/<repo>@<40-hex-sha>`), `weights_verified_by`, `weights_verified_date`, and a committed `weights_verification_artifact` path (relative to the repository root, not under gitignored `runs/`) reproduced from an audited upstream Hugging Face commit | Hardware root of trust (AMD/Intel/NVIDIA) and physical memory-bus attackers (`TEE.fail`) |
| **3** | `enclave_runtime_attested` | Hardware TEE + local proxy verifies enclave runtime and provider-signed manifest (`tinfoil-proxy` default or `privatemode-proxy` with pinned manifest), but model weights are not independently reproduced/pinned by the client | Same as Rung 2, **plus** provider build pipeline could serve altered/quantized weights under the claimed `served_model_id` |
| **4** | `zdr_contract` | Contractual zero data retention over standard TLS (e.g., DeepInfra, Fireworks with `store=False`) | Provider infrastructure sees plaintext in memory; subject to legal holds, abuse logs, or content filters |
| **5** | `standard_api` | Retaining or unspecified third-party API | Provider logs, retains, or trains on prompts/outputs |

### Why Rungs 2 and 3 are distinct (Weight Attestation Check)

Enclave attestation proves the code booted inside the CVM, not automatically which model weights were mounted after boot:

- **Tinfoil (`modelwrap` + `dm-verity`)**: Tinfoil packages Hugging Face revisions (`<org>/<repo>@<commit_sha>`) inside a digest-pinned Docker container ([`tinfoilsh/modelwrap`](https://github.com/tinfoilsh/modelwrap); [`cmd/modelwrap`](https://pkg.go.dev/github.com/tinfoilsh/modelwrap/cmd/modelwrap)) into a deterministic read-only EROFS image (`MWP` / `EMWP`) and computes a `dm-verity` Merkle root hash declared in `tinfoil-config.yml` ([`tinfoilsh/tinfoil-config`](https://github.com/tinfoilsh/tinfoil-config); [Tinfoil docs](https://docs.tinfoil.sh/)).
  - **Rung 3 (`enclave_runtime_attested`)** is the maximum posture on this Mac for Tinfoil's models (`gpt-oss-120b` at $0.15/$0.60 per 1M tokens, `deepseek-v4-1-flash` at $0.60/$1.45 ($0.01 cached; $0.65/$1.45 at initial 2026-10-31 trial), `kimi-k3-1-pro` at $4.00/$20.00 ($0.40 cached), `glm-5-3` at $1.80/$5.75 ($0.45 cached), `kimi-k3` at $4.00/$20.00 ($0.60 cached, deprecated `2026-11-12` and archived after upstream removal on `2026-11-20`), `inkling-2-small` at $0.30/$1.00 ($0.03 cached, candidate), and `gemma4-31b` at $0.40/$1.00; verified against live `/.well-known/tinfoil-proxy` and `tinfoil-config.yml` via `scripts/sync-model-catalog` on 2026-11-07 and 2026-11-20, following initial verification on 2026-10-31 in `docs/attestations/2026-10-31-tinfoil-rung3-trial.md`): `tinfoil-proxy v0.2.9` verifies the AMD SEV-SNP router enclave (`inference.tinfoil.sh`, `tinfoilsh/confidential-model-router`), pins its TLS SPKI SHA-256, and encrypts request/response bodies to its attested X25519 HPKE key, while the router enclave attests and pins each backend Intel TDX / AMD SEV-SNP model enclave (`manager/verification.go`). An independent tracker notes that "the verifier explicitly does not independently reproduce the build" ([awesome-private-inference](https://amiller.github.io/awesome-private-inference/)). Because `modelwrap` computes the `dm-verity` root hash over the packed EROFS image of the full weight directory inside a container (`195.8 GB` for `gpt-oss-120b`, `510.3 GB` for `deepseek-v4-1-flash`, `464.9 GB` for `glm-5-3`, `1.56 TB` for `kimi-k3` and `kimi-k3-1-pro`), independently reproducing `weights_hash` requires a container runtime and hundreds of gigabytes of scratch disk beyond this host's budget. Note: although a 2026-10-21 directory snapshot reported attestation "unreachable" for DeepSeek V4.1 Flash, GLM 5.3, and Kimi K3 ([confidentialinference.net](https://confidentialinference.net/providers/tinfoil)), live verification on 2026-10-31 and 2026-11-07 confirmed all registered coding models are actively attested by `tinfoilsh/confidential-model-router` (`https://inference.tinfoil.sh/.well-known/tinfoil-proxy`) because backend model enclaves (`*.tinfoil.containers.tinfoil.dev`) are reachable only from the attested router enclave on Tinfoil's internal network.
  - **Rung 2 (`enclave_weights_attested`)** is granted by `local_assist/registry.py` only when `remote_trust` also records a verified 64-hex `weights_hash`, pinned `weights_source` (`<org>/<repo>@<40-char-sha>`), `weights_verified_by`, `weights_verified_date`, and a committed `weights_verification_artifact` path (for example `docs/attestations/<model>.json`, not under gitignored `runs/`).
- **Privatemode (Edgeless Systems `Contrast` + `dm-verity`)**: Privatemode / Contrast binds `dm-verity` block-device root hashes and container digests into Kata Confidential Container `initdata` policy hashes inside a Contrast runtime policy manifest (`manifest.json`) anchored to the AMD SEV-SNP Genoa Coordinator (`snp-0-GENOA`) and Intel TDX / AMD SEV-SNP GPU worker nodes ([Contrast attestation docs](https://docs.edgeless.systems/contrast/en/latest/architecture/attestation.html); [Contrast manifest docs](https://docs.edgeless.systems/contrast/en/latest/usage/manifest.html); [`edgelesssys/privatemode-public`](https://github.com/edgelesssys/privatemode-public); [Privatemode security](https://www.privatemode.ai/security)).
  - **Rung 3 (`enclave_runtime_attested`)**: `local_assist/registry.py` enforces the generic enclave Rung 2/3 contract (`runtime: proxy`, localhost `apiBaseUrl`, non-empty `attestation_method: privatemode-proxy-contrast`, `apiKeyKeychainService`, and a localhost-bound `serve_command` validated for `--listen-address` and `--port`), while the audited Privatemode entries in `models.yaml` (verified by `scripts/build-privatemode-proxy` and `tests/test_registry_and_tools.py`) configure `privatemode-proxy` (built from pinned `edgelesssys/privatemode-public@v1.63.0` source rather than unsigned prebuilt tarballs) with `--manifest-path config/privatemode-manifest-v1.63.0.json` (`sha256: 5fa927e3b864738da35d427c10ba8e49ebeeb1531e49618899cf95f654d240c1`), `--api-key-fallback=never` (verified live on `2026-11-13` to reject cold unauthenticated `:9082` requests with `500` and warm unauthenticated `:9082` requests with `401` while forwarding `se-key-proxy`'s `Authorization: Bearer` header on `:8082`), `--workspace .home/privatemode-proxy`, `--disable-prompt-cache=false --prompt-cache-salt=random`, and strict NVIDIA OCSP policy flags (`--nvidia-ocsp-allow-unknown=false --nvidia-ocsp-revoked-grace-period=0`). In addition to TLS over the Coordinator-issued Contrast mesh CA, `privatemode-proxy` encrypts prompts and streaming SSE completions end-to-end using post-quantum hybrid HPKE (`hpke.MLKEM768X25519()`) terminating inside the attested Contrast mesh (`secret-service` + `envoy` `encryption-plugin`). Although `edgelesssys/privatemode-public@v1.63.0` publishes deterministic EROFS + `dm-verity` packing scripts (`verity/verity.sh` and `models.yaml` pinning `erofs-utils 1.9.4`, `veritysetup 2.8.7/2.8.8`, `hash_offset`, and `root_hash`), reproducing those multi-hundred-GB weight disks (`206.1 GB` for `glm-5.3-flash`, `467.8 GB` for `glm-5.3`, `65.8 GB` for `openai/gpt-oss-120b`) requires a Linux container build and hundreds of gigabytes of scratch disk beyond this host's budget, so Privatemode entries stay at Rung 3 (`weights_hash: null`) unless independently reproduced on a Linux verifier host for Rung 2.

### Freedom of Use (`usage_policy`)

A private endpoint that breaks tool calls or censors defensive security prompts reduces freedom of use:
- Every candidate must pass `scripts/eval tools <model-id>` before backing an agent alias.
- `remote_trust.usage_policy` is validated against `{"unrestricted_local", "enclave_no_inspection", "provider_filtered", "provider_terms_apply", "unknown"}`. It defaults to `unknown` on all non-local rungs so unverified provider policies are never silently recorded as unrestricted, and `unrestricted_local` is rejected off Rung 1.

1. **Private-coding admission gate (`local_assist/client.py`)**:
   - Admits Rung 1 (`local` on localhost) by default.
   - Admits Rung 2 (`enclave_weights_attested`) and Rung 3 (`enclave_runtime_attested`) via a localhost proxy **only** when explicitly opted in with `LOCAL_ASSIST_ALLOW_ATTESTED_TEE=1` **and** `routing.private_attested == "cleared"` (or when an uncleared candidate model is explicitly overridden via `LOCAL_ASSIST_ALLOW_UNCLEARED_TEE=1` / `--allow-uncleared-model` in `scripts/opencode-attested`).
   - Blocks Rung 4 (`zdr_contract`) and Rung 5 (`standard_api`) from `local-assist` private coding workflows.
2. **Outbound firewall (LuLu)**:
   - On Rungs 2-3 (enclave proxy mode), `se-key-proxy` connects only to the local vendor proxy on `127.0.0.1:<upstream_port>` and needs zero external network egress; only the vendor proxy (`tinfoil-proxy` or `privatemode-proxy`) may reach its enclave/attestation/OCSP domains. On Rungs 4-5 (direct HTTPS proxy mode), only `se-key-proxy` may reach the pinned `upstreamBaseUrl` host on port 443. `opencode`, `promptfoo`, and local MLX servers get no external egress.
3. **Out of scope today (Agent-Loop Prompt Injection)**:
   - **Agent-side prompt injection**: Even on Rung 1 (`local`) or Rung 2 (`enclave_weights_attested`), a coding agent can be hijacked by untrusted repo files or tool outputs. Guarding the agent loop against tool-output injection is out of scope for the inference transport layer and requires operator approval of interactive tool calls (`edit`, `write`, `patch`, `bash`).
4. **Hardware-backed API credential isolation (`tools/se_key_proxy/main.swift`, `tools/se_key_proxy/Package.swift`, `local_assist/se_key.py`, `scripts/se-key`)**:
   - **Standalone SwiftPM package & `scripts/se-key build`**: `tools/se_key_proxy/` includes a standalone `Package.swift` (`swift build --package-path tools/se_key_proxy -c release`) alongside the source-pinned `./scripts/se-key build` compilation into `bin/se-key-proxy`.
   - **No plaintext or environment-variable API keys**: `local_assist/registry.py` rejects `apiKeyEnvar` and plaintext `apiKey` on all non-local rungs (Rungs 2-5) and requires `runtime: proxy` on a localhost `apiBaseUrl` plus `promptfoo_provider.apiKeyKeychainService` (`free-inference.<service>`). Enclave tiers (Rungs 2-3) additionally require a `serve_command` and forbid `upstreamBaseUrl`, while Rungs 4-5 require a validated `https://<host>/v1` `upstreamBaseUrl` on port 443 and forbid `serve_command`.
   - **Secure Enclave + Touch ID sealing**: `./scripts/se-key store <service>` (or `./scripts/se-key migrate <service>`) generates a per-service hardware-bound P-256 private key inside the Apple Silicon Secure Enclave with `SecAccessControlCreateWithFlags(..., kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly, [.privateKeyUsage, .biometryCurrentSet])` (so the SE key is usable after first unlock since boot, while every unseal still requires a live Touch ID match), seals the operator's API key via ECIES (`P256.KeyAgreement` + `HKDF<SHA256>` + `AES.GCM` with service AAD), verifies write-time read-back authenticated decryption using the seal-time shared secret, and stores only the JSON ciphertext envelope (`<stem>.json`, mode `0600`, with `envelope_sha256` integrity binding) and lifecycle tombstone (`<stem>.state.json`, mode `0600`) in `~/.config/free-inference/se-envelopes/` (mode `0700`), completely avoiding macOS `login.keychain-db` `CDHash` ACL lockouts when `bin/se-key-proxy` is recompiled.
   - **Live Touch ID unlock, kernel-verified loopback upstream (`F1`), and loopback auth-injecting proxy (`se-key-proxy`)**: When `./scripts/serve-model <model-id>` starts a non-local proxy, it verifies the Swift source hash, compiler version, build stamp (`bin/.se-key-proxy.stamp`), and binary SHA-256 + `codesign -v --strict` signature, writes a provisional `"status": "starting"` PID record with a per-invocation `startup_nonce` before spawning any child (`F2`), and launches `bin/se-key-proxy proxy`. `se-key-proxy` sets `LAContext.touchIDAuthenticationAllowableReuseDuration = 0`, prompts the operator for a live Touch ID tap displaying the service, upstream destination, allowed model, request cap, and TTL, unseals the API key into process memory (`PT_DENY_ATTACH`), and listens on `127.0.0.1:<port>`. On Rungs 4-5 (`upstreamBaseUrl: https://...`), the decrypted API key exists only inside `se-key-proxy` process memory and is sent over TLS to the pinned upstream host. On Rungs 2-3 (loopback vendor-proxy mode, `127.0.0.1:<port>` -> `127.0.0.1:<upstream_port>`), `se-key-proxy` requires `--upstream-pid <upid>`, verifies via `<libproc.h>` (`proc_pidinfo` + `proc_pidfdinfo`) that `upid` (matching its startup timestamp `pbi_start_tvsec`/`pbi_start_tvusec` and `pbi_status != SZOMB`) owns the non-`SO_REUSEPORT` `TSI_S_LISTEN` kernel PCB (`soi_pcb`) on `127.0.0.1:<upstream_port>` both at startup and after each `connect()` before writing a single byte of the request or `Authorization` header (`F1`), and watches `upid` via `EVFILT_PROC` (`NOTE_EXIT`); on each forwarded request, the plaintext `Authorization: Bearer <real_api_key>` header crosses `lo0` to the verified vendor proxy socket and is transiently held in the vendor proxy (`tinfoil`) process memory under standard macOS same-UID isolation (capturing `lo0` requires `/dev/bpf*` read permissions, so the attestation trial requires a pre-flight `ls -l /dev/bpf0` check confirming `crw------- root wheel` with no `access_bpf` / `ChmodBPF` group access; `AF_UNIX` `LOCAL_PEERPID` or an inherited listening fd is the preferred future transport if `tinfoil` adds Unix socket support, `P5`). Callers (`verify-served-model`, `timing`, `eval` via `scripts/with-session-token`, and `opencode-smoke`) authenticate to `se-key-proxy` using a random per-session bearer token (`se-session-<64-hex>`, mode `0600` in `runs/.se-session-<slug>.token`, handed off via anonymous pipe FD `_FREE_INFERENCE_TOKEN_FD` in `opencode-attested` and `verify-served-model` or held in the parent `SessionAuthRelay` so `se-session-*` never enters `opencode.json`, `suite.yaml`, or OpenCode child environments); `se-key-proxy` validates the caller token, `Host` header, path allowlist (`/v1/models`, `/v1/chat/completions`), single `"model"` key (with full UTF-16 surrogate-pair decoding, `F3`), request size, `max_tokens` cap, outbound credential-leak backstop (`HTTP 400` `credential_leak_blocked`), non-blocking downstream write deadline (`--stream-timeout-seconds`, `F4`), and session request/TTL limits before injecting `Authorization: Bearer <real_api_key>` to the fixed upstream. `scripts/write-metrics` and `scripts/opencode-smoke` also record a full-tree `session_token_scan` manifest (`roots`, `missing_roots`, `excluded_dirs`, `files_scanned`, `bytes_scanned`, `files_skipped`, `matches_found`, `redactions_applied`, `remaining_unredacted_matches`, `matched_files`) in `metrics.json` and `summary.json` (if `.home/.promptfoo/promptfoo.db` or `.home/opencode-private-local` ever records a historical token leak, recovery is `rm -f .home/.promptfoo/promptfoo.db` or `rm -rf .home/opencode-private-local`, `P3`/`V2`/`R2-F2`).
   - **Trust boundary against a compromised same-UID local agent**: Because the repository checkout is writable by the current macOS user, a compromised local agent running under the same UID could modify repo scripts or `bin/se-key-proxy` before the next Touch ID tap unless the helper binary is installed root-owned (`root:wheel`, mode `0755`) outside the agent's write authority (for example `/usr/local/libexec/free-inference/se-key-proxy`) and referenced via `FREE_INFERENCE_SE_PROXY_BIN` (which `local_assist/se_key.py` verifies is owned by `root` with no group/world-writable path components).
5. **Interactive and unattended OpenCode Seatbelt isolation (`local_assist/launch.py`, `local_assist/relay.py`, `local_assist/security_profile.py`, `scripts/opencode-local`, `scripts/opencode-attested`)**:
   - **Default interactive Seatbelt (`interactive.sb`), per-invocation `service.json` custody, and parent `SessionAuthRelay`**: Every interactive CLI or TUI launch creates a `0700` per-invocation directory (`<isolated_home>/.invocations/<inv_id>/`) with a dedicated `0400` `.config/opencode/service.json` (`127.0.0.1:<ephemeral_port>` + per-invocation password), runs `opencode` inside `interactive.sb` (confining `<inv_dir>`, `<isolated_home>`, `service_port`, and `relay_port` exclusively to `(process-path "<opencode_real>")`), loads `config/plugins/credential-guard/server.js`, and routes `opencode-attested` inference through a parent-process `SessionAuthRelay` (`oc-relay-*` bearer token, `ttl_seconds` enforcement, and raw/URL/JSON-`\uXXXX`/base64/Basic-auth outbound credential-leak rejection) while reaping the per-invocation `opencode serve --service` daemon on exit. Supervisors (`AgentComms` or operator scripts) can also supply a stricter `free-inference/worker-security-profile/v1` YAML/JSON profile (or `--unattended-worker` preset), which compiles into a per-worker `opencode.json` (fail-closed `"*": "deny"` permission baseline, allowed/denied built-in and MCP tools, `allow_subagents: false` default, and per-worker `.config/opencode/service.json` custody) and a mandatory Apple Seatbelt kernel profile (`worker.sb`).
   - **Bounded filesystem read/write authority and self-modification prevention**: `worker.sb` denies `file-read-data` under `/Users` (plus `/Volumes`, `/Network`, `/private/var/folders`, `/private/tmp`, `/private/var/tmp`), allows reads only within canonicalized `read_roots`, `write_roots`, the ephemeral `isolated_home`, and validated read-only system/toolchain roots, denies `file-write*` globally except within canonicalized `write_roots` and mutable `isolated_home` subdirectories (`.tmp/`, `.local/`, `.cache/`), denies writes to `free-inference` runtime code/scripts/config/venv/Python installation paths (`_collect_runtime_write_deny_paths`) even inside a containing `write_root`, and re-applies final `(deny file-write* ...)` overrides on `isolated_home/opencode.json`, `isolated_home/worker.sb`, `isolated_home/bin`, `isolated_home/lib`, `isolated_home/runtime`, `isolated_home/.config`, `isolated_home/.worker-owner.json`, `isolated_home/.unconfirmed-process-group.json`, `isolated_home/verified-models.json`, `isolated_home/pyvenv.cfg`, and all canonicalized `protected_paths` (including `.git` with a narrow working-tree plumbing allowlist) so the worker can never modify or relax its own profile, runtime code, or hook scripts.
   - **Loopback-only two-tier kernel network filter, immutable staged `local_assist` runtime, and token relay**: `worker.sb` enforces `(deny network*)` with `(process-path ...)` loopback port allowlists (blocking non-loopback IPv4/IPv6, raw sockets, and arbitrary `AF_UNIX` sockets unless `allow_ssh_agent: true`). When `mcp.enable_local_assist: true`, a dedicated read-only Mach-O copy `<isolated_home>/bin/local-assist-python` (`0500`) and immutable runtime snapshot `<isolated_home>/runtime` (`0400`/`0500`, bound via `local_assist_runtime.pth` and run with `-I -m local_assist.server`) isolate `localhost:8080` access and imports from worker processes. In `opencode-attested`, the parent launcher runs an in-process `_WorkerTokenRelay` on `127.0.0.1:<ephemeral_port>` with a single-worker random token (`worker-relay-<64-hex>`) and finite positive `max_session_usd` ceiling so `se-session-*` tokens and `runs/` never enter the worker's environment, config files, or readable filesystem.
   - **Descriptor-pinned lifecycle, process-group reaping, and audit log harvesting**: The launcher runs the sandboxed worker inside a dedicated process group (`run_worker_sandbox_lifecycle`) with confirmed `SIGTERM` -> `SIGKILL` escalation (`.unconfirmed-process-group.json`), multi-pass start-time-revalidated reaping (`ps eww` + fail-closed `lsof -d cwd`), nonblocking `O_NONBLOCK` + `S_ISREG` + size-capped + row-deduplicated log harvesting into `runs/local-assist/`, and descriptor-pinned `openat`/`unlinkat`/`fchmod` tree removal (`_safe_rmtree_nofollow`).
6. **Settled Decisions (from Analyst Review 2026-10-29 and SE Keychain Design 2026-10-31)**:

1. **Gateway timing**: Defer LiteLLM until the second remote provider (Privatemode) is added; connect `opencode` directly to localhost endpoints first.
2. **Repository boundary**: Standalone repository with zero machine-identifying metadata or credentials committed.
3. **Second remote provider**: Privatemode (pinned manifest) after Tinfoil, so two independent enclave attestation stacks can be compared head-to-head.
4. **Local tool-calling server**: Stock `mlx_lm.server` (`0.31.3`) passed `sanity` (1/1), automated `v1` (10/10), `tools` (4/4), streaming `tools_timing.json` (`tool_call_chunks=1`), locked-down `opencode v2.0.32` standalone smoke test, and `scripts/opencode-local` end-to-end verification (`runs/2026-10-30-202125-opencode-local-e2e-aq632hjr`) with `qwen3-30b-a3b-2507-mlx-4bit`, clearing it as the primary `private-local` backend.
5. **Third-party rule**: Attested enclave providers remain third parties by default (`LOCAL_ASSIST_ALLOW_ATTESTED_TEE=1` required to opt in), with Rung 2 vs. Rung 3 enforced in `local_assist/registry.py`.
6. **Credential custody rule**: Non-local API keys never live in environment variables (`os.environ`), shell profiles, `.env` files, or plaintext config; they are sealed at rest with a Secure Enclave `.biometryCurrentSet` key and unlocked per `serve-model` session via a live Touch ID tap into `se-key-proxy`.
7. **Explicit session windows**: Interactive authorization defaults to 2h, capped at 24h per fresh Touch ID. Operator-only `session` commands expose authoritative status and immediate stop, selectable start duration, in-place renewal with token rotation and unchanged request budgets, and foreground warnings. A protected Unix control socket carries no credentials. Trusted parent relays bind replacement credentials to the live process/session/generation; workers retain independent expiry. Hard expiry and stop cancel active streams. Legacy restart flags remain available for recovery and cap changes.
8. **Unattended worker runtime, race-safe kernel reaping, and read-only custody (`v0.3.0`)**: Supervisors can launch unattended OpenCode workers from a content-pinned read-only custody export (`git archive <tag>` + hash-pinned `requirements-launcher.txt`, zero bytecode via `sys.dont_write_bytecode = True`, `--launcher-site-packages` / sibling `../env` discovery, and isolated homes under `~/.local/state/free-inference/workers`). Launchers support `--inherit-process-group` (staging `0400` `$XDG_CONFIG_HOME/opencode/service.json` so `opencode run` attaches without `--server` or passwords in `argv`/env, draining `opencode serve --service` `stderr` via reader-owned `_BoundedPipeDrain`, and publishing an initial `0600` `manifest.json` at entry with microsecond `proc_pidinfo` start times), race-safe `--reap-worker` (3-way Seatbelt `sandbox_check` allow/deny `worker_tag` discriminator + `SIGSTOP`/`SSTOP` re-verification + `648`-byte `kinfo_proc` self-calibrated `SZOMB` fallback), `AF_UNIX` MCP bridge sockets (`network.allowed_unix_sockets`, rejecting `mDNSResponder` aliases and rejecting local MCP combined with shell localhost TCP), attached-session cap inheritance (`spend.inherit_attached_session_caps`) with strict exit code `4` reservation (`launcher_exit.json`), and descriptor-pinned (`O_DIRECTORY | O_NOFOLLOW` + `dir_fd`) session stores with exact-mode `0700`/`0600` `~/.config/free-inference/active-runs.json` (`runs_dev`/`runs_ino` pinned).
